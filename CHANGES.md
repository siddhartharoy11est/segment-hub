## What changed in the product
1. The hub never sends stop commands. It ships a small signed "head" (GET /v1/catalog/head, mirrored at /v1/catalog/objects/head.json)
   that says, for each older copy of each segment, whether it is wider and what the server must do. Each server enforces that itself:
   wider strict copy stops 15 min after the server learns it is behind; consent-critical stops at once; narrower keeps serving.
2. Lease: a server that cannot read any head for 15 min stops its strict segments. A hub API outage stops nothing correct (demo button proves it).
3. Per-instance tracking: 8 server instances in 4 clusters. Singapore is 2 of 3 in sync, and the board shows that one report per cluster would hide it.
4. Why edge_sg_1 is stale is now explicit: its reload failed (it received rev 5, still serves rev 3).
5. One four-eyes principle everywhere: anything that only stops or narrows needs one person and a reason; anything that can widen needs a second person
   (publish, resume, removing a site from a list).
6. Exclusion lists have their own API (GET/POST /v1/lists/{name}, /versions, /transitions). Segments bind to Deal IDs (deal_ids), carried in the catalog and match results.
7. Exposure is a running total that only counts time past a 2 min propagation window and stops growing when a server stops the segment.
8. Wording: "eligible" instead of "ran"/"served"; held copy is "wider" or "narrower" in the API and UI.
9. Chroma (switch off with CHROMA_ON = false in public/index.html) appears only on real state: Story replay, sync board badge, submit and validation results, outage result, tests, empty and error states, docs.
